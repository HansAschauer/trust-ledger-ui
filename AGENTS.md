# AGENTS.md: trust-ledger-ui

Notes for coding agents working in this repository. The user manual is `docs/` (mkdocs); the specification and
design decisions are `docs/development/`.

## What this is

A local web page for the [trust-ledger](https://github.com/HansAschauer/trust-ledger) of a paper project. One person,
one machine: browse the claims and hypotheses of several papers, see which lack an attestation or have a stale one,
read the statement (KaTeX) next to its back-translation and Lean text, see what changed since the last attestation,
and attest one or many claims with one level and reason, each signed through ssh-agent. It also starts a fixed set
of `ledger.py` jobs (review pack, lock, verify, check, extract) in the background.

It is a front end only: no verification logic of its own, no editing of hand-written TOML, no state about the ledger
outside the ledger's own files. Version 0.0.1.

## Layout

```
src/trust_ledger_ui/
  cli.py            entry point `ledger-ui` (--init writes ledger-ui.toml)
  server.py         thin http.server layer on 127.0.0.1: token, Host/Origin checks, JSON + SSE
  core/             no HTTP, no UI; testable on its own
    ledgerio.py     the ONLY module that touches ledger.py (importlib load, version check, view models)
    config.py       ledger-ui.toml; unknown keys are an error
    attest.py       preview -> sign -> append, batches, undo
    agent.py        ssh-agent state
    jobs.py         background ledger.py commands from a fixed list
    render.py       macros from the paper preamble for KaTeX
    papermeta.py    optional paper.toml (title, edition PDFs)
  static/           index.html, app.js (Alpine.js), texlite.js, diff.js, style.css; vendor/ = Alpine.js + KaTeX
docs/               user manual; docs/images/ are generated by tools/make_screenshots.py
docs/development/   specification.md (numbered sections cited in docstrings as "SPEC.md section N"), design.md, testing.md
tests/              pytest; tests/e2e/ = browser test with playwright-core
```

## Dependency on trust-ledger

- `ledger.py` is loaded as a module from the path in `ledger-ui.toml` (`[ledger] tool`). `ledgerio.py` checks
  `REQUIRED_API` and `SUPPORTED_FORMATS` (currently ledger format `0.3.0`). If trust-ledger bumps its format, add the
  version there only after testing against it.
- Tests and screenshots expect a trust-ledger checkout next to this repo, or at `$TRUST_LEDGER`, and use its public
  `egg` example on a scratch copy. Tests skip when it is missing.
- If the UI needs something new from `ledger.py`, add it to the library API in trust-ledger (standard library only
  there) rather than reaching into its internals here.

## Hard rules

- **Server: standard library only, Python 3.11+.** `dependencies = []` in `pyproject.toml` stays empty. JavaScript
  is vendored in `static/vendor/` (see `static/VENDOR.md`); no npm build step, no CDN.
- **Security model** (`docs/security.md`, spec section 10): listen on 127.0.0.1 only, require the token, check Host
  and Origin. The browser never sends a command line or a file path; jobs are built server-side from validated names.
  The browser sends only a preview id when signing, so it cannot change what is signed after the preview.
- **Signing only through ssh-agent**, one signature per attestation (`ledger.sign_attestation` with a `*.pub`
  file). Never read a private key, never prompt for a passphrase.
- Write only the ledger's own files (`attestations.toml`, `snapshots/`) via ledger.py's functions, plus the UI's state
  dir `.ledger-ui/` (review packs) and `ledger-ui.log`, both git-ignored. Never write into the project's own review
  directory.
- Only one Lean job (`extract`) at a time: it starts Docker Lean, and parallel Docker Lean jobs break.
- Never attest or sign on the user's behalf in a real project; tests use invented people and a private agent.

## Commands

```bash
uv sync
uv run pytest                                   # unit + integration; ssh-keygen/ssh-agent/node tests skip if missing
uv run ledger-ui                                # uses ./ledger-ui.toml
uv run mkdocs build --strict                    # manual; CI deploys it to GitHub Pages on push to main
uv run python tests/e2e/run_e2e.py --playwright DIR_WITH_node_modules --trust-ledger ../trust-ledger
uv run python tools/make_screenshots.py --trust-ledger ../trust-ledger --playwright DIR_WITH_node_modules
```

When the page changes visibly, regenerate the screenshots rather than editing images by hand, and update the manual
page that describes the changed workflow.

## Style

- Docstrings cite the spec section they implement; keep `docs/development/specification.md` in step with the code.
- Manual prose: plain, short sentences, task-oriented, written for researchers, not developers.
- Commit messages: a short subject, then a paragraph on what changed and why.
